# Working glossary
Revision 24. Proposed definitions; lifecycle milestone remains OQ-002.
| Term | Meaning / boundary |
|---|---|
| Contact | Durable person identity; not a login account or separate copy at each sales stage |
| Company | Business relationship record; external partner login not implied |
| Lead | Captured, not yet qualified interest |
| Prospect | Qualified relevant interest with plausible next action |
| Client | Relationship reaching agreed transaction milestone; exact event unresolved |
| Inquiry | An incoming request linked to contact; repeat requests permitted |
| Opportunity | One potential transaction, separate from contact lifecycle |
| Handler | Current relationship responsibility; distinct from introducer and task assignee |
| Pool coordinator | Accountable for attention in pool queue; not a restrictive user role |
| Handover | Requested transfer accepted by recipient; sender retains accountability meanwhile |
| Attention reason | Explained derived condition; several may apply to one customer |
| Human attempt | Logged outbound attempt; not proof of successful conversation |
| Engagement | Named tracked interactions; definition/instrumentation required |
| Delivery | Provider/channel outcome; not customer response or human follow-up |
| Signup | Explicit registration event; staff-created contacts are separate |
| Earnings | Undefined until recognized revenue/cash/commission basis is selected |
| Watchlist | Record following or saved conditions; does not confer ownership |
Use the same term across UI, reports and contracts. Rename through configuration/migration decisions, never by silently changing historical meaning.
