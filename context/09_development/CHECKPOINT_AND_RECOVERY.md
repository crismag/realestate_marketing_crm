# Checkpoints and recovery
Model 23. Context package, not running automation.
Use bounded vertical journeys with contracts first: capture/search; claim; handover; interaction-to-attention; reminder-to-delivery; reporting drill-down.
Before slice completion: relevant checks passed or explicit recorded scoped waiver; diff reviewed; model/checklist/run log updated; current commit/working changes identified. Documentation does not configure CI.
Repair budget proposed: two focused repair attempts before reinspection and evidence handoff; owner may change it. Do not broaden into unrelated refactoring.
Before recovery inspect status and preserve unrelated changes/untracked files. Prefer a scoped forward fix or known-commit revert; never automatic hard reset, clean or force push. Database recovery, sent email and Git history are separate concerns.
At interruption persist current task/check, model revision, branch/head and patch identity, changed files, evidence/failures, environment state, blockers and next eligible action. Uncommitted work must be labeled uncommitted. Do not claim external agent monitoring or automatic host context resets.
